# 늘곁 보안·개인정보·AI 안전

## 구현된 통제

| 영역 | 구현 |
|---|---|
| 인증 | HMAC 서명 세션 쿠키(httpOnly, SameSite=Lax, 운영에서 Secure, 8시간). 운영에서 `NEULGYEOT_SESSION_SECRET`(32자+) 없으면 로그인 거부 |
| 세션 폐기 | 토큰마다 `jti` 포함. 로그아웃 시 `revoked_sessions`에 기록해 같은 쿠키를 재사용하면 401. `jti` 없는 토큰 거부 |
| CSRF | 상태 변경 요청(POST/PATCH/PUT/DELETE)은 `Sec-Fetch-Site`·`Origin`이 같은 출처일 때만 허용(403). 본문은 `application/json`만 허용(폼 전송 차단). 데모 로그인·로그아웃 포함 |
| 데모 데이터 자동 시드 | 운영(`NODE_ENV=production`)에서는 `NEULGYEOT_AUTO_SEED=true` 또는 `NEULGYEOT_DEMO_LOGIN=true`일 때만 시드 |
| 데모 로그인 | 개발 기본 허용, 운영 기본 차단(`NEULGYEOT_DEMO_LOGIN=true`일 때만). `is_demo_data` 계정만 선택 가능 |
| 권한 | 모든 서비스 함수가 역할 + 지역 범위 검사. 범위 밖 사례는 404로 존재 여부를 숨김. 요청마다 DB에서 사용자 재조회 |
| 기관 담당자 | 자기 기관 의뢰만. 기록·분석·메모 접근 불가, 의뢰 취소 불가 |
| 가족 | `family_links.consent_status = granted` + 권한 플래그. 철회 즉시(다음 요청부터) 차단. 포털 응답은 화면용 필드만 선택(내부 메모·실패 사유·분석 없음) — 테스트로 확인 |
| 입력 검증 | zod `strict` 스키마, 길이 제한, 상태 전이 서버 검증, DB CHECK/FK/UNIQUE |
| 감사 로그 | 기록·대상자·분석 검토·의뢰/조치 상태·가족 동의 변경. 본문 대신 필드명·상태값만 저장. DB 트리거로 UPDATE/DELETE 차단(append-only). 데모 초기화(`resetData`)만 트랜잭션 한정 플래그로 삭제 가능 |
| 기록 수정 | 작성자 또는 관리자만. 이전 값은 `record_revisions`에 보존. 삭제는 관리자 소프트 삭제 |
| 오류 처리 | 500 응답에 내부 정보 없음. 서버 로그에는 오류 이름과 200자로 자른 메시지만 |
| CSV | 수식 주입 방지(`= + - @` 접두 무력화) |
| AI | 서버 전용 키, 데이터 최소화(가명 코드조차 보내지 않음), 직접 식별자 마스킹(주민번호·전화·이메일·카드·도로명주소), 비신뢰 기록을 JSON으로 직렬화하고 `< > &`를 이스케이프해 `<records>` 블록을 닫을 수 없게 함, 스키마 검증, 근거 ID 대조, 근거 기록에 없는 숫자·진단명이 들어간 변화 제거, 사람 검토 필수, 속도 제한, **합성(`is_demo_data`) 대상자만 전송** |
| 음성 | 음성 파일 미저장·미업로드, 마이크 권한·녹음 상태 표시, 브라우저 음성 인식의 외부 전송 가능성 안내 |
| 긴급 상황 | 시스템이 판단하지 않음. 긴급 언급 표시 시 우선 확인 + 공식 절차 안내 + 담당자 알림 |
| 가상 데이터 | 모든 시드 행 `is_demo_data = true`, 화면 상단 DEMO 배너, 가상 도시·`.invalid` 이메일·"가상 연락처" 표기 |
| 디버그 | 디버그 엔드포인트 없음. `/api/health`는 상태만 반환 |

## 남은 위험 (운영 전 필수 조치)

1. **실제 인증 없음** — 기관 SSO/공동인증·MFA 연동, 데모 로그인 코드 제거 필요
2. **가족 관계·대리권 검증 없음** — 법적 대리권·동의서 확인 절차와 시스템 연동 필요
3. **CSRF** — Origin/Sec-Fetch-Site 검사와 JSON 전용 본문을 추가함(2026-11-06). 두 헤더가 모두 없는 요청은 운영에서만 거부하므로, 비브라우저 클라이언트를 허용하려면 별도 토큰 방식 필요
4. **속도 제한이 프로세스 메모리 기반** — 다중 인스턴스에서는 Redis 등 공용 저장소 필요
5. **DB 수준 접근 제어(RLS) 없음** — 권한은 애플리케이션 코드에서만 강제. Supabase/PostgreSQL 운영 시 RLS 추가
6. **저장 데이터 암호화·백업·보존 기간 정책 미정** — PGlite 파일은 암호화되지 않음
7. **열람 감사 없음** — 변경만 기록하고 조회 로그는 남기지 않음(이번 PR에서도 미구현)
8. **브라우저 음성 인식** — 브라우저 제조사 서버로 음성이 전송될 수 있음. 실제 운영은 계약된 STT 또는 온디바이스 방식 검토
9. **외부 AI 전송** — 실데이터를 보내기 전 개인정보 처리 위탁 계약, 국외 이전 검토 필요. 현재 코드는 실데이터 전송을 막음(아래 참조)
10. **법률·규제 검토** — 개인정보 보호법, 사회보장급여법상 정보 처리 근거, 의료기기 해당 여부(현재 진단 기능 없음) 검토 필요

## 비밀값

- `.env`, `.env.local`은 `.gitignore`에 포함. `.env.example`에는 변수명·설명만 있습니다.
- `ANTHROPIC_API_KEY`는 서버 코드(`lib/server/ai/client.ts`)에서만 읽으며 클라이언트 번들에 포함되지 않습니다(`NEXT_PUBLIC_` 접두사 없음).

## AI와 실데이터 — 현재 제한 (2026-11-06)

이 저장소는 **합성(가상) 데이터 전용**입니다. 다음 검토가 끝나지 않았으므로 실제 돌봄 데이터를 외부 AI API로 보내는 기능은 활성화하지 않았습니다.

| 미완료 검토 | 내용 |
|---|---|
| 처리 근거 | 개인정보 보호법·사회보장급여법상 민감정보(건강) 처리 근거 |
| 동의 | 정보주체(대상자·보호자) 동의 절차와 철회 처리 |
| 처리 위탁 | AI 제공사와의 개인정보 처리 위탁 계약, 수탁자 관리·감독 |
| 국외 이전 | 해외 서버 전송 시 국외 이전 고지·동의 또는 법정 요건 |
| 마스킹 | 현재 마스킹은 정규식 기반 안전장치일 뿐 비식별화가 아님. 이름·자유 서술 주소·가족 관계 등은 남을 수 있음 |

코드상 통제(`lib/server/ai/policy.ts`):

- 대상자 기록 해석: `care_recipients.is_demo_data = true`인 대상자만 전송. 그 외는 `aiStatus = "skipped"`로 기록하고 아무것도 보내지 않음.
- 음성 구조화(대상자와 연결되지 않은 자유 텍스트): 데모 모드(`NEULGYEOT_DEMO_LOGIN=true` 또는 비운영 환경)에서만 전송, 그 외 `blocked_real_data`.
- 실데이터 전송을 켜는 설정값은 일부러 두지 않았습니다. 위 검토가 끝난 뒤 별도 변경으로 추가해야 합니다.
