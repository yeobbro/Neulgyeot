# 로컬 LLM 초안 (병원용)

병원 안에서 돌아가는 LLM으로 세 가지 **초안**을 만듭니다. 외부 클라우드 LLM으로 보내는 경로는 없습니다.

| 화면 | 초안 | 적용 위치 |
|---|---|---|
| 퇴원·지역연계 → 2. 사회복지 평가 | 퇴원·연계 사회복지사 소견 초안 | `사회복지사 소견` 입력란(500자) |
| 보호자 리포트 → 리포트 작성 | 보호자용 돌봄팀 메시지 초안(쉬운 말) | `돌봄팀 메시지` 입력란 |
| 진료·간호 기록 | 교대 인수인계 요약 초안 | 화면 표시 + 복사(저장하지 않음) |

## 1. 동작 방식

```
기록 → 사실 목록(F1, F2 …) → /api/local-llm/draft → 로컬 LLM → 문장별 재검증 → "검토 필요" 초안 → 직원이 적용·수정·저장
                                   └ 미연결·실패·검증 통과 문장 없음 → 규칙 기반 초안(기록 사실 나열)
```

- **사실 목록만 보냅니다.** 화면 아래 "보내는 기록 사실 보기"에서 무엇을 보내는지 그대로 확인할 수 있습니다.
  - 소견·보호자 메시지에는 이름, 생년월일, 연락처, 진단 코드, 약 이름을 넣지 않습니다.
  - 보호자 메시지는 그 리포트에 **포함된 항목만** 씁니다. 리포트 항목은 보호자 공유 설정 범위를 따릅니다.
  - 인수인계는 병원 내부용이므로 최근 기록, 활력징후, 투약 기록 상태를 씁니다.
- **문장마다 근거 표시:** 초안의 각 문장 옆에 근거 사실 ID(F1 등)가 붙습니다. 마우스를 올리면 원래 사실이 보입니다.
- **서버 재검증** (`lib/local-llm/verify.ts`): 아래 중 하나라도 걸리면 그 문장은 버립니다.
  - 근거 ID가 없거나, 보내지 않은 ID를 인용함
  - 인용한 사실에 없는 숫자·날짜·시각
  - 근거에 없는 부정 표현 (예: 참여 기록이 있는데 "기록이 없습니다")
  - 기록에 없는 평가 표현 (예: "좋았습니다", "훌륭한 하루")
  - 진단·예후·처방 변경·위험도·긴급도·자격 판단, 안심시키는 표현, 낙인 표현
  - 한국어가 아닌 문장, 글 자체를 설명하는 문장, 중복 문장
- **자동 반영 없음:** "적용"은 입력란에 글을 넣을 뿐입니다. 저장·전송·승인은 기존 절차(임시저장, 동의 검토, 리포트 검토·승인)를 그대로 거칩니다.
- **합성 데이터만:** API는 합성 DEMO 환자(`SYN-P-…`)와 `dataClass: "synthetic"` 요청만 받습니다. 사실에 전화번호·주민번호 형태가 있으면 거부합니다.
- **기타 보호:** 같은 출처 요청만 받고(전용 헤더 + Origin 확인), 분당 12회 제한이 있습니다. 프롬프트와 모델 출력은 로그에 남기지 않습니다.

재검증은 숫자·날짜·부정·금지 표현 같은 **형식적 불일치**만 잡습니다. 문장의 뜻이 사실과 맞는지는 완전히 검증할 수 없으므로, 직원 검토가 반드시 필요합니다.

## 2. 데모: Mac + Ollama

```bash
brew install ollama
ollama serve &
ollama pull qwen2.5:7b          # 메모리 16GB 이상 권장. 8GB 장비는 qwen2.5:3b

LOCAL_LLM_MODEL=qwen2.5:7b npm run build && LOCAL_LLM_MODEL=qwen2.5:7b npm start
```

`LOCAL_LLM_MODEL`이 없으면 패널에 "로컬 LLM 미연결 · 규칙 기반"이 표시됩니다. 이때는 규칙 기반 초안만 씁니다. Vercel 미리보기처럼 로컬 LLM에 닿을 수 없는 배포에서도 같습니다.

## 3. 운영: 병원 추론 서버로 교체

코드 수정 없이 주소만 바꿉니다(OpenAI 호환 `/v1/chat/completions`).

| 변수 | 기본값 | 설명 |
|---|---|---|
| `LOCAL_LLM_MODEL` | — | 없으면 꺼짐 |
| `LOCAL_LLM_BASE_URL` | `http://127.0.0.1:11434` | vLLM 등. http는 localhost·사설망 IP만 허용, 그 밖에는 https |
| `LOCAL_LLM_API_KEY` | — | 서버가 Bearer 키를 요구할 때만. 커밋 금지 |
| `LOCAL_LLM_TIMEOUT_MS` | 120000 | |
| `LOCAL_LLM_MAX_TOKENS` | 900 | |

실데이터 사용 전 필요한 것(현재 미구현): 로그인·권한, 감사 로그 영속화, 개인정보 영향평가, 모델·라이선스 검토, 기관 보안 검토.

## 4. 모델 선택

| 모델 | 라이선스 | 메모 |
|---|---|---|
| Qwen2.5 7B/14B Instruct | Apache-2.0 | 권장 |
| Qwen2.5 1.5B/3B | Apache-2.0 | 저사양 데모용. 문장이 어색하고 검증에서 버려지는 문장이 많습니다 |
| EXAONE 3.5 | **비상업 라이선스** | 도입 전 라이선스 검토 필요 |

## 5. 확인 결과 (2026-11-25, 개발 환경, CPU 2코어)

- 단위 테스트: 사실 최소화, 요청 게이트(합성 환자·식별자·개수), URL 정책, 파싱(코드 블록, 인용 표시, 문단 분할), 재검증(수치·날짜·M/D 날짜·부정·평가·권고·판단·한국어), 폴백, 헬스 체크.
- 앱 E2E(Playwright, Ollama), 세 화면 모두 초안 생성 → 적용 확인:
  - `qwen2.5:3b`: 인수인계 7문장, 퇴원 소견 7문장(소견란 적용 349/500자), 보호자 메시지 1문장(2문장은 검증에서 제외). 화면당 약 1분.
  - `qwen2.5:1.5b`: 사실과 반대되는 부정 문장(참여 기록이 있는데 "기록이 없습니다")이 나와 부정 표현 검사를 추가함. 보호자 메시지는 검증 통과 문장이 없어 규칙 기반 초안으로 대체됨.
- 검증 규칙을 추가하게 된 실제 출력 예: "정상 수준을 유지했습니다", "건강 관리가 잘 이뤄졌습니다", "필요한 조치를 취해야 합니다", "주의가 필요합니다"(모두 기록에 없는 평가·권고).
- 남는 한계: 검증을 통과한 문장도 뜻이 조금 달라질 수 있습니다(예: 기록은 "난간 사용"인데 초안은 "난간 사용이 필요한 것으로 기록"). 그래서 "검토 필요" 표시와 직원 적용·수정 단계를 없애지 않습니다.
- 확인하지 않은 것: 7B 이상 모델(이 개발 환경의 메모리 한도로 실행 불가), vLLM 서버, Mac 실기기.
